# 流量 webhook 移植与采集升级

## 插件

旧插件为 TrafficReport，接收端使用 JSON `{ "message": "..." }` 和完整 Authorization 请求头。新实现复制原启用状态、地址、认证头和 Top 5，保存在私密 SQLite 表，管理 GET 只显示配置状态和主机名。

上海时间安排：每天 00:00 发送前一天日报，每周日 00:00 发送截至前一天的七天周报，每月 1 日 00:00 发送上个完整自然月月报。

新服务 mboard-traffic-reports.service 由 timer 每分钟检查发送安排和重试队列。首次启用仅从下一报告时间开始，历史补发需要管理员显式操作。

## 真实连接验证

唯一请求标识 `migration-webhook-test-v1`，消息明确标注为“mboard Webhook 迁移测试（真实发送）”，只包含测试标记和时区。

实际目标按原配置发送，返回 HTTP 200。队列记录 status=sent、attempts=1。新 timer 的第一次 service 执行 Result=success、ExecMainStatus=0。

旧配置精确比较：地址一致、Authorization 一致、top_limit 一致。检查过程没有输出原地址的私密路径、Authorization 和报告中的用户邮箱。

## 管理入口

[站点设置](https://panel.example/#/admin/settings)包含“流量 Webhook”“报告预览”和“发送记录”。每日、每周和每月预览均用真实已授权管理员 API 读取；公网浏览器检查三种消息头格式均正确。屏幕中保留一个 h1，390px 布局横向溢出为 false，页面运行错误数组为空。保存密码字段留空保留原值，清除使用明确控件。预览使用原文只读显示。

预览包括历史统计口径提示。发送报告前确认用户邮箱、身份和排行会发到已保存接收端。状态区分排队、处理中、已发送、失败和取消。

## 采集版本

mboard-node 0.2.1 从已签发的 traffic_labels 元数据识别身份出口 UUID，按 `(user_id,node_id,profile_id)` 分区上报。空身份字段继续省略，旧待确认批次和累计游标保留原内容。完整升级不改变节点原生配置和配置版本。

## 边界和数据口径

- 迁移前原档案的身份出口子集从物理节点总量中扣除一次，保留原排行逻辑。
- mboard 0.2.0 采集时已经合并的出口流量保留在节点总量，原维度无法倒拆。
- 接入前 UTC 日期的整日记录按同名上海日期计入一次。新小时明细按上海自然日准确分窗。报告携带升级边界提示。
- 投递是至少一次。远端已接收而本地确认之前断电时，同一消息可能重试。稳定 X-Mboard-Delivery-ID 可由接收端去重。
- 设置变化会取消旧配置待发送任务，正在远端处理的请求不能撤回。

## 测试

225 个后端场景通过，10 个浏览器场景通过，24 个 POSIX/BusyBox 安装场景通过。

Go race、vet 和实际代理核心双身份 TCP 采样通过：同一用户、节点的两个出口分别收到 16 上传、18 下载字节，三次累计查询保持分区，合计 32 上传、36 下载。

SSRF 检查每次校验所有 DNS 地址，HTTPS 连接固定到已验证地址，保持原 Host 与 TLS 验证。Bun 1.3.14 的真实本地 TLS 测试验证了自定义 lookup 固定连接行为。原接收端只发送了一条明确授权的迁移测试。
